# Eval Space · 本地评估工作台

个人本地版，将 Judge Studio、网页截图评估、生成式 UI 实验室放在一个工作空间里。平台只监听 `127.0.0.1`，默认端口 `3088`。

## 开始使用

推荐 Node.js 24。双击项目根目录的 **启动评估工作台.command**，浏览器会自动打开工作台。

也可以执行 `npm run platform`，访问 http://127.0.0.1:3088 。开发时按 Ctrl+C 退出。

首次使用需要各工具已经安装依赖：在根目录、`pc-screenshots` 分别运行 `npm install`。`seed-demo` 无第三方依赖。工作台自身没有新增第三方依赖。依赖缺失时，页面会提示在哪个目录安装。

双击 **停止评估工作台.command** 停止平台及它启动的工具服务。停止前请先完成或保存工具里的任务；正在执行的任务不会自动迁移到后台。独立启动且被平台复用的服务会继续运行。

## 第一版能力

- 概览：真实服务状态、历史记录统计、快捷工具入口。
- 项目空间：创建项目、归档/恢复、关联/移出已有评估和截图记录。
- 报告中心：按来源和名称/模型搜索；Judge Studio 报告在工作区内打开；截图批次进入原工具后按名称选择。
- 任务中心：查看截图批次最近保存的进度与自动评估的已保存结果。暂停、继续和中断仍在各工具中操作。
- 工具工作区：按需启动本地服务，保留已打开的 iframe；导航切换不刷新工具。刷新整个浏览器仍会重载所有工具，请先保存任务。
- 设置与环境：一键启动全部工具、依赖/端口错误提示、运行日志、本机环境信息。
- 平台不会启动多平台采集服务，也不会轮询其浏览器状态。截图工具仍由用户主动启动浏览器。

## 数据与配置

- 项目元数据：`data/platform/projects.json`，原子写入并串行处理并发修改。
- 平台启动的服务日志：`data/platform/logs/`。
- 原工具记录留在原目录。服务在线时，平台优先通过只读 API 汇总运行中工具的记录，避免复用其他目录的服务时出现列表不一致；离线时通过 `lib/records.mjs` 读取 Judge Studio 的 `data/runs/*/summary.json` 与截图工具的 `pc-screenshots/batches/*/batch.json`。
- 关联项目不会移动、复制或删除原始记录。原记录被移除时，项目会提示关联记录不可读取。
- 多平台采集（AI Lens）已从工作台下线，导航、快捷入口、状态检测、全部启动均不再包含它。`AI-Lens-local/` 的独立代码与历史数据保留。
- 各工具的模型密钥、评分规则和浏览器配置沿用已有设置。第一版提供集中设置入口，没有自动合并或迁移密钥。

## 服务管理

工具注册表位于 `lib/catalog.mjs`。先健康检测，再按需启动；不杀占用端口的未知进程。启动的子进程使用独立进程组，平台退出只结束自身拥有的进程。Judge Studio 由平台启动时使用 `JUDGE_HOST=127.0.0.1`；原有独立/云端启动方式保持默认监听行为。

页面与平台 API 分离，`lib/projects.mjs` 是项目存储接口，`lib/records.mjs` 是记录适配器，`lib/services.mjs` 是本地执行器。未来上云时可以替换存储和执行器，保留页面与大部分业务接口；账号权限、远程任务协议、云存储及部署配置仍需要后续适配。

## 验证

运行 `npm run test:platform` 验证项目存储、并发保存、记录适配、跨站写入拦截、服务健康检测和进程退出。测试使用临时目录和模拟服务，不调用模型、不采集真实网站、不发布数据。

原 Judge Studio 回归检查：`node --test test/*.test.js`。
