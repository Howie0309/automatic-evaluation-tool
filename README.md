# Judge Studio

一个本地运行的自动评估工作台：自定义 System/User Prompt、OpenAI 兼容模型与 API 地址，上传 Excel 后预览并批量执行评估。

OpenAI 模型通过 Responses API 调用，并支持按模型配置推理强度；其他服务商继续使用 OpenAI 兼容的 Chat Completions 接口。

OpenAI 评估可选择关闭、自动或强制联网搜索。搜索使用 Responses API 的 `web_search` 工具；结果详情会展示搜索词和可点击的引用来源，结果 Excel、CSV 和 JSON 也会保留这些信息。联网会增加耗时和工具调用费用，因此默认关闭。

模型输出格式完全由 Prompt 决定。工具会原样保存 JSON、纯文本或其他输出；可选的“分数字段路径”只用于生成分数统计，不参与成功/失败判定。

结果表会优先按 System Prompt 中声明的 JSON 变量分列，同时补充模型实际返回的额外字段。嵌套对象会递归展开为 `父字段.子字段`，长度不固定的数组则合并保留在一个字段中；纯文本输出单独显示在“模型输出”列，错误和中断信息不会重复复制成功结果。Excel 和 CSV 导出会完整保留原始 Excel 的所有列、Markdown 文本和单元格内换行，再在右侧追加评估状态和模型输出；重名的评估字段会自动加 `评估_` 前缀。

每次保存的评估都带有独立交互报告页，可在浏览器中查看各评分维度均分、分页预览 case、全文搜索、按状态筛选、控制输出字段显隐、展开单条输入与结论并复制完整模型输出，无需先下载 Excel。报告会自动识别 `score`、`*.score`及 `score.*` 等数值评分字段，但不自行推断满分或合格线；如果 Judge Prompt 没有输出分数，则保留通用结果预览，不强制生成分数。

运行时可配置 0–3 次自动重试。连接重置、超时、HTTP 429 和常见 5xx 错误会按指数退避重试；鉴权、Prompt 或参数错误不会重试。结果详情和 CSV 会记录实际请求次数。

批量运行支持暂停、继续和中断。暂停时不再调度新 Case，当前请求会正常完成；中断会取消当前请求、停止后续调度，并保留已经完成的结果。

## 启动

```bash
npm install
npm run dev
```

然后访问 `http://localhost:3077`。

## 云端部署

### 腾讯云免费体验版（HTTP 云函数）

项目内置 `cloudbaserc.json` 和 `scf_bootstrap`，可部署到现有 CloudBase 免费体验环境。线上版本使用静态托管 + HTTP 网关 + HTTP 云函数；Excel、评估结果和导出文件写入云存储，运行索引写入文档型数据库，不依赖云函数的临时磁盘。

```bash
tcb fn deploy judge-studio --force --yes
tcb service create -p api -f judge-studio
tcb routes edit --data '{"domain":"*","routes":[{"path":"/api","enablePathTransmission":true}]}' --yes
tcb hosting deploy ./public judge-studio --safe --verify --entry index.html,report.html
```

浏览器访问需开启腾讯云匿名登录，并用 OPA 只放行所需的 `/api/*` 函数路由。平台不再要求额外的自定义访问密码。免费体验版额度用尽后会停服，不会自动转为按量扣费。

### Docker / 云服务器

项目包含 `Dockerfile`、`docker-compose.yml` 和 Caddy HTTPS 反向代理配置，可部署到阿里云、腾讯云或百度智能云的国内 Linux 云服务器。`judge_data` 数据卷持久保存上传的 Excel 和评估结果，容器更新不会清空。

云端建议使用绑定到服务器的域名，由 Caddy 自动提供 HTTPS。可复制 `.env.deploy.example` 为 `.env.deploy`，填写域名后运行：

```bash
docker compose --env-file .env.deploy up -d --build
```

API Key 仍然只在当前浏览器会话与评估请求中使用，不会写入服务器文件。

## Excel 格式

支持 `.xlsx`。第一行需要是列名。上传后可手动指定“问题列”和“回答列”，所以列名无需固定为 `query` / `answer`。其他列也可通过 `{{列名}}` 在 User Prompt 中引用。

本地版评估数据集单文件最大 300 MB（300 × 1024 × 1024 字节），前后端同步校验；评审规则附件仍为 100 MB。大文件解析和预览会占用较多内存，解析期间请勿重复上传。该上限不代表云端网关或第三方托管平台也允许 300 MB 请求。

### 数据集内嵌图片

支持 Excel 普通“插入图片”（PNG/JPEG/GIF/WebP）。图片按左上角所属单元格匹配工作表、列和真实 Excel 行号，跨行图片不会重复分给相邻 case；仅有图片的行也会保留。表头图片和整表背景不属于待评数据，会明确提示不发送。IMAGE 外链和 DISPIMG 公式图片暂不解析，选中的 case 会明确阻止评估，需先转换成普通插入图片，不能当成空白继续。

上传后在“待评图片列”勾选要发送的列（默认全选）。图片列独立于文本 Prompt 变量映射；映射到图片列的变量会增加“见本条附图”标记。数据预览、单条详情和交互报告支持缩略图及原图查看。每条请求只携带当前工作表、真实行号和已选列的图片，以视觉内容加入待评 User 消息，与共用的评审规则图片分开。必须选择支持视觉输入的模型和图片透传的 API 代理；图片会计入模型输入费用。

待评图片与规则图片都会在发送前检查实际像素尺寸：长边超过 8000 像素时，整图等比例缩至长边 8000，完整保留画面，不切片、不裁剪；未超限的图片保持原始字节，不放大、不重新编码。JPEG 使用高质量编码，其余格式缩放后转为无损 PNG。原始 Excel、提取的图片、规则缓存与原图预览不变，只转换请求中的副本；结果详情与报告显示原图和实际发送尺寸，JSON 保存处理元数据，不重复保存缩放副本。模型或代理可能还会内部缩放、限制图片总数量或字节大小，8000 像素并非所有接口的通用兼容保证。

每条待评数据最多 30 张图片、合计 20 MB；超限需减少图片列或压缩原图。整个数据集最多 5000 张图片，解压后的图片合计最多 600 MB。原始 Excel 保持不变，提取图片保存为本地上传记录的附件；浏览器只接收图片元数据并按需加载预览，不一次传输所有 Base64。历史 JSON 保存图片引用和来源，Excel/CSV 追加“待评图片来源”列，不把原图 Base64 塞入单元格；原图可从原始 Excel、详情或报告查看。永久删除最后一条引用该上传文件的记录时，对应提取图片也会随上传文件一起清除。

升级前上传的数据需重新上传才能生成图片附件；旧评估结果不会被补写成“已看图”，必须重新评估。

User Prompt 中的每个 `{{变量}}` 都会生成一项 Excel 列映射。工具会自动匹配常见的 query、answer、A/B 回答、分值和备注字段；未映射变量会阻止运行，也可明确选择“固定为空”。

## 评审规则附件（Excel / PDF）

在 System Prompt 下方的“评审规则文件”中，可独立上传一个 `.xlsx` 或 `.pdf` 评分标准或示例文件（最大 100 MB）。Excel 可勾选一个或多个工作表，并分别填写 `A1:D20` 这样的单元格范围；留空表示整个工作表。

PDF 支持文字版与扫描版。上传后可填写 `1-3,5` 这样的页码范围，点击“读取选中页”应用；页码为文件实际页序（从 1 开始），不是正文印刷页码。30 页以内默认读取全部，超过 30 页必须手动选择范围，不会自动截断。修改页码后必须重新读取才可开始评估。刷新后可复用已保存的选中页面，若要修改范围需重新上传原 PDF。

PDF 在本地服务使用 PDF.js 提取文字并将选中页面渲染为 JPEG，文字和页面图像一并发送，保留表格、插图、截图及原始版式。扫描件不额外执行 OCR，依靠视觉模型阅读页面；仍须选择支持图片输入的模型，API 代理也须透传图片，不依赖代理的原生 PDF 文件接口。页面最长边最多 2400 像素、最多约 400 万像素，细小文字建议放大预览确认清晰度。每次最多 30 页，页面图像合计最多 20 MB、文字最多 20 万字符；超限需缩小范围。加密 PDF 需先解除密码保护。本地运行需 Node.js 22.13+ 或 24+，无需安装系统 Poppler。未内嵌中文字体的 PDF 会使用可用的系统中文字体回退；其他电脑应安装 Noto Sans CJK SC 等中文字体，或上传内嵌字体的 PDF。

规则按真实单元格坐标转成文字，首行和单元格内换行会保留，合并单元格标注完整范围。展开“预览发送给模型的规则”可确认选中的文字与图片；每条评估都会将文字规则附在原 System Prompt 后面。读取公式已保存的计算结果，不执行公式。选中文字最多 20 万字符，超出时须缩小范围，不会静默截断；实际可用长度也受所选模型的上下文限制。

支持 Excel 插入的 PNG、JPEG、GIF、WebP 内嵌图片，纯图片工作表也可选择。图片与所选单元格范围相交时，会携带完整画面和来源位置发送；超长图片按上述 8000 像素规则缩放，不裁剪、不转成 OCR 文字，动态图只供模型读取静态画面。选中图片最多 30 张、合计 20 MB，整个上传文件内的图片合计最多 40 MB。发送前与处理后的图片分别检查大小限制，超限或格式不支持会明确报错，不会静默丢弃图片。工作表背景图作为整表参考图保留。图片按 OpenAI Responses 或 OpenAI 兼容 Chat Completions 的视觉消息格式发送，规则配图和本条待评内容在不同消息中明确标注。所选模型和 API 代理必须支持图片输入；本工具不能保证第三方代理实际执行视觉识别。

`IMAGE` 外链公式和 `DISPIMG` 公式图片暂不直接解析，选中时会要求先转换成 Excel 的“插入图片”，不会仅拿公式结果或错误值继续评审。

浏览器用 IndexedDB 保存所选规则图片和 PDF 页面，普通配置中仅存图片元数据和缓存标识，避免 Base64 图片占满 localStorage。重新上传规则会替换旧图片缓存，移除规则或重置工作台会清除该缓存。刷新后可复用规则，重新上传可调整范围。每次评估的 JSON 记录保存完整文字与图片快照，历史结果详情的折叠 System Prompt 区域可预览当时使用的配图。原始规则 Excel / PDF 不作为待评数据集保存，不会覆盖待评数据或变量映射。

## API Key

API Key 仅存放于浏览器的 `sessionStorage`，并随每次评估请求传给本地服务，由本地服务代理请求模型接口；它不会写入项目文件。

## 文件与结果保存

- 上传的 Excel 会自动保存到 `data/uploads/`。
- 每次评估完成或中断时，已产生的结果会自动保存为 Excel、JSON 和 CSV，位于 `data/runs/`。
- 页面中的“已保存记录”可重新下载原始 Excel、结果 Excel、JSON 和 CSV。
- 历史记录可在二次确认后永久删除；仍被其他记录引用的原始 Excel 不会被误删。
- `data/` 已被 Git 忽略，不会推送到 GitHub；API Key 不会出现在保存文件中。
